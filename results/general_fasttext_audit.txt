  dim = 300

  model = cbow

NOTE: this is the general-purpose model exactly as released by Facebook AI
Research (not trained by us) - it is used only as a fixed feature generator,
concatenated with the custom Medical FastText (Phase 5) in Phase 7. Its CBOW
training and minn=maxn=5 setting differ from our custom Medical FastText
(skip-gram, minn=3/maxn=6, guide 7.1), which is expected and does not need to
match: the guide only fixes hyperparameters for the model we train ourselves.

## Out-of-vocabulary subword construction test

Per guide 7/9: "FastText can construct vectors for unseen spellings from
subwords, so an unseen medical/Banglish token does not have to collapse to a
single generic UNK vector." Verified on three strings absent from the
1.48M-word vocabulary:

  'jorer'      in_vocab=False  vector_shape=(300,)  vector_norm=0.341
  'gastricer'  in_vocab=False  vector_shape=(300,)  vector_norm=0.259
  'napa500mg'  in_vocab=False  vector_shape=(300,)  vector_norm=0.115

All three produced valid, non-zero 300D vectors via subword hashing rather
than failing or returning a null/zero vector - confirms OOV handling works
as required before this model is used in Phase 7's token representation
pipeline.

## Conclusion

embeddings/cc.bn.300.bin is verified genuine, correctly dimensioned (300D),
semantically coherent, and capable of constructing OOV vectors for unseen
Banglish/medical spellings. Ready for use as the fixed "General FastText"
input in Phase 7 (600D = 300D general + 300D medical).
